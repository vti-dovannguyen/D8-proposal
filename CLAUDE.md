# D8 Portal — System Map

Internal team portal for D8 division (VTI). Next.js App Router + Prisma/Postgres + NextAuth (Google, domain-restricted) + Supabase Storage. UI text is Vietnamese.

> Keep this file in sync when you add a model, lib function, server action, route, or nav item.

## Stack

- **Next.js 16.2** (App Router, React 19, Server Components + Server Actions). This is a breaking Next version — read `node_modules/next/dist/docs/` before writing framework code (see `AGENTS.md`).
- **Prisma 7** with the `@prisma/adapter-pg` driver adapter. Client is generated to `src/generated/prisma` (do not hand-edit). Postgres via pooled `DATABASE_URL` (pgbouncer port 6543).
- **NextAuth v5** (`next-auth@5 beta`), JWT session strategy, Google + Credentials (email/password) providers, Prisma adapter.
- **Supabase Storage** for files (private bucket, signed URLs).
- **Tailwind CSS v4**, **lucide-react** icons.
- **Tiptap** + **TinyMCE** rich-text editing; **sanitize-html** for server-side HTML sanitization; **htmlparser2**/**domhandler** for HTML→Markdown export (`lib/html-to-markdown.ts`).
- **Vitest** (unit) + **Playwright** (e2e).
- **xlsx** (SheetJS) for server-side Excel parsing (user import).

## Routing & auth flow

- `src/proxy.ts` — Next middleware (named `proxy` in this Next version). Redirects unauthenticated users to `/login` and authenticated users away from `/login`. Excludes `api/auth`, `api/health`, static assets.
- `src/lib/auth.ts` — NextAuth config; `Google` + `Credentials` (email/password against `User.password`) providers; exports `handlers`, `auth`, `signIn`, `signOut`, `isAllowedEmail`, `authorizeCredentials`, `backfillPasswordForNewUser`. `isAllowedEmail(email, domain)` restricts sign-in to `ALLOWED_EMAIL_DOMAIN` (default `vti.com.vn`). `jwt`/`session` callbacks inject `user.id` and `user.role` (default `MEMBER`) into the token/session.
- `src/app/login/page.tsx` — sign-in page. `src/lib/auth-actions.ts` — `signOutAction()`.

## Roles & permissions

Roles (`src/types/index.ts`): `ADMIN`, `DIVISION_LEADER`, `SECTION_MANAGER`, `PM`, `MEMBER`.

- `src/lib/permissions.ts` — `can(role, capability)`, `isManager(role)`. EDITORS = ADMIN/DIVISION_LEADER/SECTION_MANAGER/PM; MANAGERS = those minus PM.

## Directory layout

- `src/app/(portal)/` — authenticated app; `layout.tsx` renders the shell (sidebar/header). Each feature folder has `page.tsx`, `actions.ts` (server actions), and client form/widget components. The `/dashboard` page renders a unit "Tình hình Billable / RA" section (3 rolling months, computed EE/PO + per-project breakdown, manager-editable headcounts) above the meeting-status widget. The `/` home page shows: a "Thống kê D8" block (total employees with Official/Intern split, total projects with Open/Close split), recent documents with file-type icons (via `file-types.ts`), and a manager-only "Warning" section (left: active projects missing the current week's report — name appears in no current-week `MeetingEE` row, shown only after the weekly deadline; right: users with no active allocation, excluding ADMIN/DIVISION_LEADER).
- `src/app/api/` — `auth/[...nextauth]`, `agents/chat` (streaming chat), `health`.
- `src/components/` — `layout/` (sidebar, header, shell-chrome), `home/` (announcement-list, quick-access, recent-activity), `ui/` (confirm-button, states), `bookmark-button`, `pagination`.
- `src/lib/` — server/domain logic (see below).
- `src/types/` — `index` (roles/capabilities), `meeting`, `knowledge`, `community`, `next-auth.d.ts`.
- `prisma/` — `schema.prisma`, `seed.ts`. `tests/` — unit + `tests/e2e/`.

## Data model (`prisma/schema.prisma`)

- **Auth**: `Account`, `Session`, `VerificationToken`, `User` (role, `employeeType` OFFICIAL/INTERN, section, title, `dateOfBirth`, `gender`, `password` — bcrypt hash, nullable, defaults to `Vti@1234` for every user via a one-off backfill script). Intern effort counts at half an official member's (allocation effective hours + EE denominator).
- **Meetings**: `Meeting` (week — now selected from a fixed 2026 dropdown of Saturday–Friday weeks, see `lib/meeting-week-options.ts` — weekRange, optional structured `weekStart`/`weekEnd` DateTime mirror of the Từ/Đến inputs used by `getWeeklySummaryReport`, category — including the "Summary Weekly" rollup category selectable by SECTION_MANAGER or DIVISION_LEADER, not a stored master-data value; picking it auto-fills a fixed Executive Summary template when the field is still empty — `projectStatus` (On Schedule/Late/Issues, `lib/meetings.ts#PROJECT_STATUSES`), `divisionEE` (nullable EE%, entered via a single number input for every non-PM role — the EE - Effort section no longer exposes the per-project `eeRows` table for manual editing; the detail page colors it red/green against the `NORM` env var, see `lib/meetings.ts#getEeNorm`), status DRAFT/OPEN/CLOSED, section, optional `projectId` linking the meeting to one `Project`, summaries; the create/edit form hides RA - Resource Allocation from the UI (raRows stays in the schema, still populated by `syncWeeklyTasks`/`eeRows` and shown read-only on the detail page), hides EE - Effort/Division Issues/Company Issues/Other Information entirely for role PM, and Division/Company Issues no longer let the user pick an owner — new issues are always owned by the current session user), `MeetingEE` (effort plan/actual; no longer directly editable in the form, only populated by PM-tool sync and rendered on the detail page), `MeetingRA` (resource allocation), `Risk` (Issues/Risks row: `type` "Issue"|"Risk", title, impact `Severity` shown as Priority, `actionPlan` shown as Mitigation/Action, status, `planDate`; belongs to exactly one of `meetingId`/`groupId` — both nullable), `Milestone` (Milestone row: name, `planDate`, status — see `lib/meetings.ts#MILESTONE_STATUSES`, note; same `meetingId`/`groupId` either-or as `Risk`), `NextWeekPlan` (Next Week Plan row: keyActivity, note; same `meetingId`/`groupId` either-or as `Risk`), `MeetingGroup` (the "Chi tiết theo nhóm / Sub-project" section — name/status/`progressNote`/`order`, each with its own `milestones`/`risks`/`nextWeekPlans` — shown on the create/edit form INSTEAD OF the flat Milestone/Issues-Risks/Next Week Plan sections when `Meeting.project.hasSubProjects` is true), `Attachment` (single-file upload post-creation, plus multi-file staging directly on the create/edit form via `lib/storage.ts#assertUploadableFile` + `actions.ts#persistAttachmentFiles`, validated before the meeting record is written), `Issue` (severity, linked as Division/Company issues to meetings), `Project` (name/code/category/section/active, `picPms` — many-to-many with `User`: a project can have several PIC PMs, and a member can be PIC for many projects + integration fields: `repoProvider`/`repoUrl` GitHub/GitLab, `pmTool`/`pmUrl` Redmine/Backlog, `accessKey` write-only token for AI MCP health checks, `hasSubProjects` — when true, the Weekly Report create/edit form swaps the flat Milestone/Issues-Risks sections for the per-sub-project `MeetingGroup` editor), `ProjectAllocation` (resource allocation: optional member, project `role`, optional `skill`, `hoursPerDay`), `ProjectEnvironment` (test environments: name/url/username/password write-only/note/status), `ProjectMonthlyDetail` (per-project monthly billable/effort man-months: billable/develop/warranty, calendar member/intern/collaborator, OT member/intern/collaborator, absent, plus manual `eeToMonth`; unique `[projectId, month]`), `ProjectKpi` (KPI Loại A: one row per member awarded a KPI in one month on one project — `month` "YYYY-MM", `kpiType` (always `"A"` today; the column exists so loại B/C need no migration), optional free-text `note`; unique `[projectId, month, kpiType, userId]`).
- **Knowledge**: `Document` (file, version, tags), `WikiPage` + `WikiVersion` (history), `Tag` (shared across documents/wiki/topics).
- **Community**: `Topic` (likes, pinned, bookmarks), `Comment`, `Announcement` (title, rich-text `body` (sanitized HTML), `pinned`, `active` ON/OFF status, author; no expiry — `active` controls visibility on home widget + header bell), `Bookmark` (polymorphic: topic | agent).
- **AI**: `AIAgent` (prompt, useCase, rating), `AgentChatThread` + `AgentChatMessage` (role USER/ASSISTANT), `AIAccount` (shared AI subscriptions with members; `email` is no longer globally unique — the same email may be issued to several projects, one `AIAccount` row per email+project pair, deduped at the app level rather than by a DB constraint since `project` is nullable free text; `assignedToId` — single person accountable for the account, separate from the `members` who merely have access).
- **Master Data**: `MasterCategory` (type/value/order/active — DB-backed category lists read live by forms, unique `[type,value]`), `Skill` + `UserSkill` (per-member skill with level 1–5), `CertificateType` + `UserCertificate` (per-member certificate: issuer, issuedAt, expiresAt, credentialId, fileUrl), `UnitMonthly` (unit-level manual monthly headcounts: lbQaOt/intern/official, unique `month` "YYYY-MM"; feeds the dashboard Billable/RA overview).
- **Point Award**: `PointAward` (monthly point award: `month` "YYYY-MM", `type` PERSON/PROJECT, nullable `userId`/`projectId` target, `points` 0–100, `reason`, `notified`/`notifiedAt`, `createdById`, optional `imageUrl` (Supabase path, chat-only notification image); unique `[month,userId]` and `[month,projectId]`).

## `src/lib` function reference

- **db.ts** — `db` (singleton PrismaClient with pg adapter).
- **meetings.ts** — `canEditMeeting(role, status)` (editors only, not CLOSED), `eeTotals(rows)`, `buildClonePayload(source, next)` (carries eeRows/raRows/risks/milestones/nextWeekPlans/projectStatus/divisionEE over to the clone), `getEeNorm()` (reads env `NORM`, default `EE_NORM_DEFAULT` = 90), `milestoneStatusClass(status)` (pill color for Milestone status). Fixed UI constants (not Master-Data-driven): `SUMMARY_WEEKLY_CATEGORY`, `SUMMARY_WEEKLY_TEMPLATE` (Executive Summary auto-fill HTML), `RISK_TYPES` (`["Issue", "Risk"]`), `RISK_STATUSES`, `MILESTONE_STATUSES` (`["On Track", "At Risk", "Not Started", "Completed"]`), `PROJECT_STATUSES` (`["On Schedule", "Late", "Issues"]`), `EE_NORM_DEFAULT`.
- **meeting-week-options.ts** — `generateWeekOptions(startWeek, startWeekFriday, endWeek)` (pure): Saturday→Friday week spans (Saturday = 6 days before "this Friday", so adjacent weeks never share a boundary date, which the Summary Weekly rollup query matches by date only) with `weekStart`/`weekEnd` as `"YYYY-MM-DDT00:00"`/`"YYYY-MM-DDT23:59"`. `MEETING_WEEK_OPTIONS` = weeks 29–53 of 2026, the fixed dataset the "Tuần" select box on the create/edit form uses (needs regenerating for 2027).
- **knowledge.ts** — `parseTags(raw)`, `normalizeSearchQuery(raw)`, `inlineContentType(ext)`.
- **search.ts** — `runFullTextSearch(query)` — ranked Postgres FTS (`to_tsvector`/`websearch_to_tsquery`, `simple` config) across Document + WikiPage, injection-safe, no GIN index yet.
- **community.ts** — `canDeleteTopic(role, authorId, userId)`, `agentMockReply(agent, message)` (deterministic offline reply).
- **announcements.ts** — `activeAnnouncementWhere()` (`{ active: true }`) + `htmlToText(html)` (pure tag-strip for previews).
- **storage.ts** — Supabase: `uploadToBucket` / `uploadAttachmentFile` (octet-stream + forced download, XSS guard), `uploadDocumentFile` (inline mime for preview), `getSignedUrl`, `getSignedDownloadUrl`, `assertUploadableFile` (shared extension/size validation, called before any DB write for both the single- and multi-file attachment paths). 50MB cap, extension allowlist (no html/svg/js).
- **rich-text-tables.ts** — `normalizeRichTextTables(html)` (pure): forces rich-text tables to fit the layout so the Weekly Report sections never scroll sideways. Rescales every `<col>` width in a `colgroup` to percentages summing to 100% (preserving the author's relative proportions when TinyMCE/Excel wrote pixels), sets the `<table>` to `width:100%;table-layout:fixed`, and strips `<th>`/`<td>` fixed widths in favour of `word-break:break-word` so long cell text wraps. Idempotent, and only emits properties on `sanitize.ts`'s style allowlist so it survives re-sanitization. Emits `<col …>` un-self-closed to match sanitize-html's own output.
- **sanitize.ts** — `sanitizeRichTextHtml` / `sanitizeWikiHtml` (server-only; whitelist tags/attrs — includes TinyMCE's accordion tags `details`/`summary`/`div.mce-accordion-*` and fixed-width table tags `colgroup`/`col`, plus a `width`/`min-width`/`max-width`/`text-align`/`table-layout`/`word-break`/`overflow-wrap` `style` allowlist on `table`/`colgroup`/`col`/`th`/`td` so accordions and tables set in the Weekly Report Executive Summary editor still render on the meeting detail page — the last three exist because `rich-text-tables.ts` writes them and a second sanitize pass would otherwise strip them). Also exports **`sanitizeMeetingRichTextHtml`** = `normalizeRichTextTables(sanitizeRichTextHtml(html))`: used by every Weekly Report rich-text field both on save (`meetings/actions.ts`) and on render (`meetings/[id]/page.tsx#RichHtml`), so tables stored before the normalizer existed also fit with no data migration.
- **html-to-markdown.ts** — `htmlToMarkdown(html)`: converts already-sanitized rich-text HTML (the same fixed tag set `sanitizeRichTextHtml` allows) into Markdown, via `htmlparser2#parseDocument`. Tables become GFM tables, accordions become a raw `<details><summary>` block with a Markdown body. Not a general-purpose converter — only handles tags that allowlist can produce.
- **weekly-summary-export.ts** — `buildWeeklySummaryMarkdown(input)`: assembles the "Export Markdown" button's file content on a Summary Weekly meeting detail page — week name, time range, Executive Summary (via `htmlToMarkdown`), EE - Effort Efficiency table, Issues/Risks table, and the "Report nguồn được tổng hợp" rollup (via `weekly-summary-report.ts#queryWeeklySummaryReport`), one table per section.
- **openai-agent.ts** — `generateAgentReply`, `createAgentReplyStream` (OpenAI Responses API, falls back to mock when `OPENAI_API_KEY` unset; model via `OPENAI_MODEL`, default `gpt-4.1-mini`).
- **pm-integrations.ts** — `fetchWeeklyTasks(project, weekStart, weekEnd)` pulls the week's tasks from a project's configured PM tool (Redmine via `X-Redmine-API-Key` + `issues`/`time_entries`; Backlog via `apiKey` + `/api/v2/issues`), using the write-only `Project.accessKey` server-side only. Each `WeeklyTask` also carries best-effort `priority`/`category`/`milestone`/`dueDate`/`createdAt` (Redmine: `priority`/`category`/`fixed_version`/`due_date`/`created_on`; Backlog: `priority`/`category[0]`/`milestone[0]`/`dueDate`/`created`) for the Weekly Progress Report. Helpers: `isPmConfigured`, `toDateOnly`, `parseRedmineTarget`, `parseBacklogTarget` (both prefer `Project.code` as the PM identifier only when it looks like a real key — `/^[A-Za-z0-9_-]+$/` — else fall back to the `/projects/<KEY>` path, guarding against a `code` that's actually a copy-pasted display name).
- **weekly-report-template.ts** — builds the Executive Summary HTML for `syncWeeklyTasks` per the team's fixed Weekly Progress Report template (Tổng quan / Tiến độ theo hạng mục / Vấn đề & Rủi ro / Hành động / Kế hoạch tuần tới / Phụ lục). All tables/numbers (`computeWeeklyReportStats`, `groupByCategory`, `selectRiskTasks`, `selectHighlights`) are computed deterministically from the fetched tasks so they never depend on the LLM; `buildWeeklyReportHtml` assembles the final HTML (sanitizer-safe — matches `sanitizeRichTextHtml`'s allowlist). The three narrative slots (`overallNote`/`escalationNote`/`nextWeekPlan`) can optionally be supplied by an LLM via `buildNarrativePrompt`/`parseNarrativeResponse` (strict JSON reply, `NARRATIVE_SYSTEM_PROMPT`) and otherwise fall back to a plain deterministic sentence — so sync still produces a complete report with no `OPENAI_API_KEY` configured. Section 3 risk criteria: status = Blocked, OR overdue, OR priority = High and not done. There's no historical snapshot store, so the template's "Tuần trước"/trend columns always render "—".
- **master-data.ts** — constants: `MEETING_SECTIONS`, `MEETING_CATEGORIES`, `PROJECT_CATEGORIES`, `WIKI_CATEGORIES`, `DOCUMENT_CATEGORIES`, `TOPIC_CATEGORIES`; `ProjectOption` type.
- **projects.ts** — `normalizeAllocation(row)` (single, returns `null` for empty) + `normalizeAllocations(rows)`: validate/clean project resource-allocation rows (role required, hours 0–24, empty member/skill → null). `effectiveHoursPerDay(hours, employeeType)`: interns count at half (`INTERN_EFFORT_FACTOR`). `projectVisibilityWhere(role, userId)`: row-level project visibility for the Weekly Meeting screens — a PM only sees projects where they're one of the PIC PMs, everyone else sees all active projects. `isProjectPic(picPms, userId)`: whether userId is among a project's PIC PMs.
- **project-access.ts** — `requireProjectEditAccess(projectId)`: server-only auth gate for editing an existing project's info — throws unless the caller is a manager or a PM who is one of the project's PIC PMs (via `isProjectPic`); used by `projects/actions.ts#updateProject`/`updateProjectIntegration` and every mutation in `projects/[id]/actions.ts`. Creating/deleting projects and bulk import stay gated by `can(role, "project:manage")` directly (managers only).
- **skill-matrix.ts** — pure helpers for the Skill Matrix screen: `levelMeta` (0–5 label + Tailwind classes), `LEVELS`, `LEVEL_HEX`, `levelDistribution` (count of assignments per level 1–5), `avgPerSkill` (mean level per skill).
- **master-data-db.ts** — server-only category reader. `getCategoryValues(type)` / `getCategoryMap(types)` return active `MasterCategory` values ordered, falling back to the `master-data.ts` constants when the table is empty. `CATEGORY_TYPES` (PROJECT|DOCUMENT|TOPIC|MEETING|MEETING_SECTION|WIKI), `CATEGORY_LABELS`, `CATEGORY_FALLBACK`. Forms (meeting/project/document/wiki/topic + admin filter) read categories via this.
- **monthly-detail.ts** — pure helpers for the Project Monthly Detail tab: `ee(row)` (= billableProject / (calendarMember + calendarIntern × `INTERN_EFFORT_FACTOR` + otMemberEffort − absent) × 100, 0 when denominator ≤ 0; intern calendar effort weighted at half), `eeStatus` (green ≥90 / amber ≥80 / red), `EE_THRESHOLDS`, `eeDenominator`, `monthlyTotals`, `EFFORT_FIELDS`, `parseMonthlyPaste(text)` (TSV paste → rows + errors; `ee` column ignored, `eeToMonth` stored).
- **unit-report.ts** — pure helpers for the dashboard Billable/RA section: `rollingMonths(from)` (current month + next 2, "YYYY-MM"), `aggregateUnitReport(rows, months, projectNames)` (→ per-project `billableProject` rows + unit `po` = Σ billableProject + `ee` = Σ billableProject / Σ eeDenominator × 100), `monthLabel`. Reuses `eeDenominator` from `monthly-detail.ts`.
- **point-award.ts** — pure helpers for the Point Award screens: `validatePoints` (int 0–100), `rankAwards` (points desc, tie-break earlier createdAt), `splitPodium` (top 3 vs rest), `formatMonth`, `POINT_AWARD_TYPES`/`POINT_AWARD_TYPE_LABELS`.
- **project-kpi.ts** — pure helpers for the KPI Loại A screens: `KPI_TYPE_A`/`KPI_TYPES`/`KPI_MONTH_RE`, `normalizeKpiInput({month, kpiType, entries})` (validates `YYYY-MM`, guards `kpiType`, de-dups members, blank note → null, requires ≥1 member), `distinctMonths` (newest first), `sortKpiRows` (month desc → project → member), `KPI_EXPORT_HEADERS`/`buildKpiExportAoa(rows)` (header row + one array per KPI, the AOA the Excel export writes) and `kpiExportFileName(month)` (ASCII-only, so `Content-Disposition` needs no encoding). Month labels reuse `point-award.ts#formatMonth`.
- **kpi-a-report.ts** — server-only query layer shared by the `/kpi-a` page and its Excel route so the table and the file can't drift: `canViewKpiList(role)` (manager or PM — same rule as the nav item), `kpiProjectWhere(role, userId)` (a PM sees only projects they're PIC PM on; deliberately does NOT filter on `active`, so KPI history survives a project closing), `normalizeKpiFilters` (a malformed month is ignored, not an error), `queryKpiARows`, `queryKpiAFilterOptions`.
- **google-chat.ts** — `buildPointAwardCard` (pure Cards v2 JSON; renders an optional celebration GIF + uploaded photo image widget) + `sendPointAwardCard` (POST to `GOOGLE_CHAT_WEBHOOK_URL`; no-op/false when env unset; never throws). `buildMeetingReportMessage` (pure plain-text) + `sendMeetingReportNotification` (POST to `MEETING_CHAT_WEBHOOK_URL`; no-op/false when unset; never throws) — fired on weekly-meeting creation.
- **user-import.ts** — `normalizeUserImportRows(rawRows, domain)` (pure): maps Excel rows (Name/Account/Date of Birth/Gender) → `{email,name,dateOfBirth,gender}`, builds email `{account}@{domain}`, skips blanks, de-dups by email.
- **file-types.ts** — `fileTypeMeta(fileName)` (pure): extension → `{ key, label, tone }` for document icon rendering.
- **weekly-report.ts** — pure helpers for the home Warning section: `parseWeekRange` ("DD/MM – DD/MM/YYYY" → start/end), `isWithinWeek`, `parseDeadlineEnv` (env `WEEKLY_REPORT_DEADLINE`, default FRI 10:00), `weeklyDeadline`, `isPastDeadline`, `missingReportProjectNames`.
- **permissions.ts**, **nav.ts**, **auth-actions.ts** — see above. **auth.ts** — NextAuth config; `Google` + `Credentials` (email/password against `User.password`) providers; `session: { strategy: "jwt" }`; exports `isAllowedEmail`, `authorizeCredentials`, `backfillPasswordForNewUser` in addition to `handlers`/`auth`/`signIn`/`signOut`.

## Server actions (by feature `actions.ts`)

- **meetings**: `createMeeting`/`updateMeeting` (both take an optional `filesFormData: FormData` of staged attachments under the key `"files"`, validated via `persistAttachmentFiles`/`assertUploadableFile` before the meeting row is written, so a rejected file never leaves an orphan/duplicate meeting; `createMeeting` also posts a Google Chat meeting-report notification to `MEETING_CHAT_WEBHOOK_URL`; required-field validation is skipped entirely when `status === "DRAFT"`, powering the form's "Lưu nháp" Save Draft button), `closeMeeting`, `cloneMeeting`, `uploadAttachment` (the original single-file path, key `"file"`, reuses the same validation helper), `syncWeeklyTasks(projectId, weekStart, weekEnd)` (PM-tool sync → Weekly Progress Report Executive Summary via `lib/weekly-report-template.ts` + EE effort row; editor-only), `getWeeklySummaryReport(weekStart, weekEnd)` (SECTION_MANAGER or DIVISION_LEADER only: one row per Meeting — any section/project — whose `weekStart`/`weekEnd` overlaps the given range, with each referenced project's general info attached via `lib/weekly-summary-report.ts#buildSummaryRows`; powers the meeting form's "Summary Weekly" category, see `summary-weekly-report.tsx`). All of these are editor-gated (`meeting:edit`), and additionally project-gated for role `PM`: a PM may only touch a meeting tied to a project where they are one of the (possibly several) PIC PMs, or (for no-project meetings) the meeting's own creator — enforced via `assertProjectAccess` in `meetings/actions.ts` (checks membership via `isProjectPic`/`canManagePmMeeting`); row-level visibility for the list/project pickers uses `projectVisibilityWhere` — helpers live in `lib/projects.ts`.
- **knowledge/wiki**: `createWiki`, `updateWiki`, `deleteWiki`.
- **knowledge/documents**: `createDocument`, `uploadNewVersion`, `deleteDocument`.
- **topics**: `createTopic`, `addComment`, `likeTopic`, `pinTopic`, `deleteTopic`.
- **agents**: `createAgent`, `deleteAgent`.
- **account** (new): `changePassword` — self-service password change; verifies the current password, validates the new one (min 6 chars, must match confirmation), updates the hash. Route `/account` — linked from the header avatar/name.
- **announcements**: `createAnnouncement`, `updateAnnouncement`, `deleteAnnouncement` — guard `announcement:manage` (MANAGERS), sanitize rich-text `body`, persist `active`/`pinned`. List page shows OFF rows to managers only; the portal header bell + home widget read active announcements.
- **projects**: `createProject`, `deleteProject`, `importProjects` guard `project:manage` (managers only — create/delete/bulk-import never open to PM). `updateProject` (also persists `ProjectAllocation` rows via `normalizeAllocations`) and `updateProjectIntegration` (repo/PM/accessKey) instead guard via `requireProjectEditAccess` (`lib/project-access.ts`): a manager can edit any project; a PM can edit only a project where they're one of the (possibly several) PIC PMs. Route `/projects` filters the list the same way (`picPms: { some: { id: userId } }` for a PM, unfiltered for managers) and the client (`project-form.tsx`) hides Create/Delete/Import for a PM, only ever rendering Edit on rows the PM already owns.
- **projects/[id]**: `createEnvironment`/`updateEnvironment`/`deleteEnvironment`, `addAllocation`/`updateAllocation`/`deleteAllocation`, `addMonthlyDetail`/`updateMonthlyDetail`/`deleteMonthlyDetail`/`importMonthlyDetails`, `updateServerInfo`, `getEnvironmentPassword`, `addProjectKpis`/`updateProjectKpiNote`/`deleteProjectKpi` (KPI Loại A; `addProjectKpis` validates via `lib/project-kpi.ts#normalizeKpiInput` then `createMany({ skipDuplicates: true })`, so re-awarding an existing member+month is a silent no-op, and revalidates `/kpi-a` as well) — all guard via `requireProjectEditAccess(projectId)` (same manager-or-PIC-PM rule as above; `getEnvironmentPassword` looks up the environment's `projectId` first). Route `/projects/[id]` — project detail (header + tabs: Môi trường test, Git/Backlog/Redmine, AI accounts, Phân bổ nguồn lực, Chi tiết theo tháng, List KPI Loại A, Thông tin server); view-for-all, edit for managers or the project's PIC PM(s); project name in the list links here. ## Read-only routes (no `actions.ts`)

- `/kpi-a` — "List KPI A" sidebar item (nav visibility `MANAGER_OR_PM`): every project's KPI Loại A rows, columns Tháng/Dự án/Member/Ghi chú, sorted month desc → project → member, filtered by `?month=&projectId=` through `kpi-a-filter.tsx`. Rows are written from the project detail tab, never here. Query + visibility live in `lib/kpi-a-report.ts`. A "⬇ Xuất Excel" link carries the active filters into `GET /api/kpi-a/export`.

## API routes

- `POST /api/agents/chat` — streaming agent chat (uses `openai-agent`).
- `GET /api/kpi-a/export?month=&projectId=` — Excel (SheetJS `XLSX.write`) export of the KPI Loại A list, gated by `kpi-a-report.ts#canViewKpiList` and using the same query as the `/kpi-a` table, so the file always matches what the caller can see and has filtered. Returns a header-only sheet when nothing matches.
- `GET /api/health` — health check.
- `/api/auth/[...nextauth]` — NextAuth handlers.

## Environment variables (runtime)

- `WEEKLY_REPORT_DEADLINE` (optional, default `"FRI 10:00"`) — weekly-report submission deadline; the home Warning section flags projects missing a current-week report only after this time in the current calendar week.
- `MEETING_CHAT_WEBHOOK_URL` (optional) — Google Chat incoming-webhook URL; `createMeeting` posts a plain-text weekly-report notification here (needs `APP_URL` for the clickable detail link). Unset → silently no-ops.
- `NORM` (optional, default `90`) — EE% threshold read by `lib/meetings.ts#getEeNorm`; the meeting detail page colors the Division EE value (`Meeting.divisionEE`) red when below it, green at/above.
